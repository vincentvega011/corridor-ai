# Corridor AI Execution Evidence Index

Everything here is synthetic sandbox evidence. Each claim points to the file that shows it. A passing run is evidence that the listed code paths behave as stated in the sandbox; it is not evidence of production safety.

## How to reproduce

```bash
make evidence      # six scenarios through the real API: docs/evidence/runs/
make test          # 1384 passed
make test-safety   # 466 passed
make web-e2e       # 42 passed (browser tests, screenshots in docs/evidence/screens/)
```

`make evidence` (`scripts/evidence_run.py`) starts its own API (port 8300) on its own database (`<name>_evidence_e2e`) in cassette replay mode with the demo clock (10 October 2026), resets the sandbox before each scenario, drives the scenarios over HTTP exactly as the customer app and the bank console do (button flows and recorded chat lines only), and writes `docs/evidence/runs/<scenario>/`:

| File           | Content                                                                                                                                |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `log.md`       | steps, request summaries (a TOTP is shown as `<code>`), decisions with rule ids, balances, chain check, expected-versus-observed table |
| `ledger.jsonl` | the ledger entries the scenario produced (digit runs of 9 or more, tokens, seeds removed)                                              |
| `state.json`   | balances, transfers, payees and locks before and after, read from the sandbox database                                                 |
| `chain.json`   | the hash-chain verification output after the scenario                                                                                  |

`docs/evidence/runs/results.json` has the machine-readable outcome of every check.

## Limitations

- Replay mode: the recorded model answers make the runs repeatable. They do not show live model behaviour, and no live provider call is part of this package.
- The evaluation report is a one-seed preview that predates the current code; the expanded suite is not evaluated (provider quota). Do not read the report as a final benchmark.
- Scenario F's tamper uses an administrator connection to a scratch database, which the application cannot do; the point is that the verifier notices.
- The scenarios cover the demonstrated paths, not every rule; the rule-level coverage is in the test suites and the red-team cases (`eval/redteam/`, 125 cases).
- Synthetic data only. No external penetration test or audit was performed.
